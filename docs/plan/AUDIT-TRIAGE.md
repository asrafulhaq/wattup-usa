# Audit triage, 3 September 2026

Checklist B.7: `pnpm audit --json` re-run in both apps after the F8 upgrades (`next` 16.3.4,
`better-auth` 1.7.2) and the B.11 `dompurify` bump. Nothing was upgraded on the branch that
wrote this file; every "upgrade now" below is work for its own branch.

**How to read it.** One row per advisory and vulnerable version range, as pnpm reports them
(the same GHSA id appears twice where two major lines of a package are both present).
"Reachable" answers one question: does code this app executes, in the browser or on the
server, ever load the vulnerable package? It was answered by grepping every import in
`app/`, `components/`, `lib/`, `scripts/` and `prisma/` for the package name and by reading
the dependency paths pnpm prints. Tooling that only ever runs on this repository's own files
(lint, build, the Prisma and shadcn CLIs) is not reachable, whatever its severity.

|---|--:|--:|--:|--:|--:|--:|--:|
| `wattup-frontend` | 83 | 106 | 0 | 33 | 64 | 9 | 98 |
| `wattup-proforma` | 3 | 3 | 0 | 2 | 1 | 0 | 3 |

`--prod` stays high on the frontend for three reasons that are not runtime exposure: the
`shadcn` CLI is listed under `dependencies`, `@prisma/client` carries the `prisma` CLI in its
tree, and `next`'s `styled-jsx` carries `@babel/core`. The one advisory in code the frontend
executes is `@tiptap/core`.

**The three things worth doing, in order:**

1. **`@tiptap/*` to 3.30.4 or later**, in lockstep across the 30 TipTap packages. The only
   runtime advisory (`mergeAttributes()` promotes an own `__proto__` key to DOM attributes).
2. **`prisma`, `@prisma/client`, `@prisma/adapter-pg` 7.8.0 to 7.10.0.** wattup-proforma is
   already there, and its audit shows that line drops the `@prisma/dev` chain (`hono`,
   `@hono/node-server`, `fast-uri`, `valibot`), which is 31 of the frontend's rows. Prisma
   7.10.0 still ships `mysql2` 3.15.3 and `deepmerge-ts` 7.1.5, so those three rows remain in
   both apps until Prisma moves.
3. **Housekeeping at the next tooling bump:** move `shadcn` to `devDependencies`, remove
   `eslint-plugin-turbo` (unreferenced by `eslint.config.mjs`), and `pnpm update` the build
   chain patches (`postcss`, `nanoid`, `immutable`, `picomatch`, `brace-expansion`,
   `js-yaml`). None of these changes what is deployed; they shrink the report so a real
   runtime advisory is visible when it arrives.
