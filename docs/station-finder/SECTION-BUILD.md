# Locations page: station finder section

Branch: `feat/locations-station-finder`
Replaces: the city grid in `components/drivers/expanding-us-drivers.tsx` on `/locations`

## Spec: what is true when this is done

1. `/locations` shows a California map with a marker for each signed site, in light
   mode, matching the reference frame: flat land shapes, no roads, no POI labels,
   small dot markers, one accent colour.
2. A search bar sits above the map with four segments: address or postcode, distance,
   filters, submit. `Use My Location` sits beneath it.
3. Typing a city, site name or postcode narrows both the map and the list. Results are
   sorted by distance from the search point when there is one.
4. `Use My Location` asks permission at the moment of intent, never on load, and
   degrades to a readable message when refused.
5. Selecting a marker or a list card selects the other, and opens a card showing site
   name, address, charger count and status.
6. Every marker carries a status: no site is live yet, so a visitor is never misled
   into driving to one.
7. Filter and selection state lives in the URL, so back works and links are shareable.
8. The section renders on the server with the full list in HTML, and is usable with
   JavaScript disabled.
9. No WebGL. The section is interactive on a low end phone with no GPU context.
10. Nothing from the internal columns of the signed-locations sheet reaches the browser.

### Out of scope on this branch

Prisma model and dashboard CRUD, per-station detail pages, real geocoding of arbitrary
street addresses, turn by turn directions, live availability, amenities filtering.

## Why SVG rather than a map library

The reference is an illustration, not a slippy map. Measured, not assumed:

| | Inline SVG | Mapbox GL JS |
|---|---|---|
| Payload | 21.7 KB raw, ~6 KB gzipped | ~230 KB before one tile |
| Network at runtime | none | tile requests per pan |
| WebGL context | none | required |
| Blocked on a token | no | yes |

Geometry is real US Census county data, generated by `scripts/build-ca-geometry.mjs`,
not hand drawn. Mapbox stays the plan for the full finder once the token lands and
arbitrary address geocoding is needed; this section does not need it.

## Assumptions I am building on

- **Coordinates are city level for now.** No geocoder yet, so sites are placed at city
  centroids. At state zoom that is under a pixel of error. They must be replaced with
  real geocoded site coordinates before any zoomed in view ships.
- **Address search is local.** Matching runs against city, site name and postcode of
  the 27 sites, which covers the realistic queries. Arbitrary street addresses need a
  geocoder and are deferred.
- **The list replaces the city grid, not supplements it.** Capacity, site type and
  status move into the result cards.
- **Accent is WattUp blue `#197dff`**, amber reserved for coming soon status.

## What could break, and what catches it

- **Markers drift off the coastline.** Projection constants must match the ones the
  paths were baked with. `CA_PROJECTION` is exported from the generated file for
  exactly this reason. **Verified:** all 27 sites project inside real California county
  polygons (point in polygon against the generated geometry), and the north/south axis
  is the right way up.
- **Section is a client island and kills SSR of the page.** The list renders on the
  server; only the map and controls are the island.
- **URL state fights the existing `?showAll=true`.** That parameter goes away with the
  grid; check nothing else links to it.
- **Found while checking:** `components/home/hero.tsx:44` and
  `components/home/expanding-us.tsx:48` both link to
  `/locations?showAll=true#locations`. The parameter becomes inert, which is harmless,
  but the new section must keep `id="locations"` so those links still land correctly.

## Corrections found while building

- **23 cities, not 25.** The figure in both plan documents came from a parse that
  counted duplicates. Counted from the sheet: 27 sites, 162 chargers, **23 distinct
  cities**, 11 ordered for 2026 and 16 for 2027. Both documents corrected.
- **One address defeats text parsing.** `11265 Camino Ruiz San Diego, CA 92126` has no
  comma before the city and no street suffix to cut on, and silently produced a blank
  city. City is now taken from a postcode registry rather than parsed, and the script
  throws rather than emitting a blank.

## Testing note

This project has no test runner: `package.json` defines `lint` but no `test`. The
projection was verified with a throwaway point in polygon script rather than a
committed unit test. Adding a runner is a separate decision, not something to slip into
this branch unannounced.
