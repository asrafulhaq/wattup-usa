*WattUp Station Finder — approach, stack and plan*

Short version: a light-mode map + location finder for the 27 signed California
sites, built on a stack that carries straight over to Singapore and Thailand
without a rewrite. Initial version ready for review *Friday 4 Sep*.

*1. Map platform — Mapbox GL JS (via react-map-gl)*
The reference look is defined by what has been *removed* from the basemap: no
roads, no POI labels, flat grey land, small dot markers. Mapbox Studio is a
visual editor for exactly that, so hitting the reference frame in light mode is
a design task, not a fight. Cost at our traffic: 50,000 map loads/month free,
then $5 per 1,000, so realistically $0. Singapore and Thailand are covered day
one, local-script labels from the same style. Because we sit behind
`react-map-gl`, the whole thing swaps to free self-hosted MapLibre + Protomaps
in about a day if we ever want off the invoice.

We do *not* need Three.js or React Three Fiber. Mapbox is already a WebGL
renderer and a second WebGL context costs frames for no visual gain. GSAP
(already installed) does the sliding tab indicator and card transitions.

*2. Architecture*
Locations become a real record in the database we already have, managed from
the dashboard we already have. Nobody needs a developer or a deploy to add a
site or flip one live.
• Neon Postgres + Prisma `Location` model, CRUD in the existing /dashboard
  with the RBAC already in place
• `/locations` server-rendered: SEO copy, full list in HTML, works with JS off
• Map is a client island that only loads when it scrolls into view
• One static page per station (`/locations/redlands-w-colton-ave`) with
  LocalBusiness schema — "EV charging near Redlands" is a query people type,
  and a map alone is invisible to it
• All state lives in the URL, so back works, links are shareable, and support
  can send a customer straight to a station

*3. Data workflow — seed first, dashboard after*
The 27 sites go into the seed file once (addresses geocoded at import, so
coordinates are baked in and nothing geocodes at page load). One command
populates a fresh database. From that moment the dashboard owns everything:
add a site, edit an address, flip PLANNED to LIVE, publish/unpublish. Saving
refreshes the public map with no deploy. The seed never overwrites a row that
has been edited in the dashboard, so a deploy can't silently revert a status
someone changed that morning.

*4. Search and location*
• Address / postcode search with autocomplete, biased to the active market
• "Use my location" via the browser, permission asked at the moment of intent
• Distance filter 5/10/25/50/100, unit from the market — miles in California,
  km in Singapore
• Filters for status, connector type, charger count, amenities, each showing
  its result count
• List and map are one thing: hover a card and its marker lifts, select and
  the map flies to it, list always sorted by distance
• Empty states do real work — "No stations within 25 miles. Nearest is Loma
  Linda, 38 miles away" with a button to widen the radius

*5. Performance*
A map library is ~200KB before a single tile, so it never sits in front of the
first paint. Server-rendered placeholder holds the slot, map loads on scroll.
Markers are WebGL layers with clustering, not DOM nodes — fine at 27, and the
same code holds at 500 for the Asia rollout. Budgets I'll hold the build to:
LCP under 2.0s on a mid-range phone on 4G, map interactive within 1.5s of
entering view, 60fps panning, `/locations` document under 40KB before the map.
Motion respects the system reduced-motion setting.

*6. Built for the second market, not the first*
`market`, `country`, `timezone` and `distanceUnit` are in the schema from day
one. Adding Singapore is one config file plus rows in a table, not a refactor.
New markets get their own path (`/sg/locations`, `/th/locations`) so each can
rank in local search. Units, address order and phone formats are never
hardcoded. Copy is externalised from the start, so Thai translation is a file
rather than a hunt through the code. The tab strip from the reference becomes
the market switcher when there is more than one.

*7. Schedule*
• *Wed 2 Sep* — data model + migration, dashboard CRUD, import and geocode the
  27 sites, market registry, GeoJSON endpoint
• *Thu 3 Sep* — Mapbox Studio light style, map canvas, clustered markers, live
  vs coming-soon marker states, station card, GSAP tab strip
• *Fri 4 Sep* — search bar, filters, use-my-location, results list, mobile
  bottom sheet, station detail pages, performance + accessibility pass.
  Preview URL for review end of day.

*Deliberately not in v1:* turn-by-turn directions (the button hands off to the
phone's map app), live availability and pricing (needs the chargers
commissioned and a live feed), driver reviews, per-site photography. Each is a
clean addition later; none of them changes anything above.
